# rcgui-plugin-kvault

RCGUI 的插件，用来把一台 K-Vault 站点配成 rclone 远程，并且在插件里直接列目录、删文件、上传。填站点地址和访问令牌，测通，建出一个 `webdav` 类型的远程，带上 K-Vault 需要的几个参数；之后站点上的文件在这一页里管。另外接管从主程序内建版 K-Vault 搬过来的设置，以及卸载前的导出恢复。

站点地址、认证头、表单字段、错误文案全在这个插件里。主程序不认识 K-Vault，也不知道站点地址是什么，它只做一件通用的事：把用户这次在面板里选中的那一个文件的字节，按插件给的说明发出去（见 [HOST-CONTRACT.md](HOST-CONTRACT.md) 的 H8）。

## 它建出来的是什么

rclone 里没有 `kvault` 这个后端。K-Vault 站点讲的就是 WebDAV，另外多认几个参数，所以远程的类型是 `webdav`：

```
[k-vault]
type = webdav
url = https://kv.example.com/dav
vendor = other
kvault = 1
kvault_folder =
kvault_storage = telegram
kvault_dedup = 1
bearer_token = kvault_xxx_yyy
```

插件做三件事：把地址补成 `/dav`、带着令牌打两个探测接口、调 `config/create` 把上面这份参数写进 rclone。它不会凭空造出一个新后端。

## 装载

0.3.2 **还没有发布**：没有 tag，Release 里也没有这个 zip。下面这条是发版之后的路径，现在想试就先在本地打包（见「开发」）。

1. 从 Release 下 `kvault-0.3.2.zip`（正文里有这个 zip 的 sha256，可自行核对）。
2. 解到 `<RCGUI 数据目录>/plugins/kvault/`，目录里应当有 `config.json`、`main.wasm`、`check.sha256`。
3. 在插件页启用。启用后「新建远程」的类型下拉里才会多出 K-Vault 这一项。

宿主需要 0.3.2 及以上（`config.json` 的 `min_gui_version` 写的就是这个）：面板分页与 `remote_types` 元数据从 0.3.1 起才有，而 0.3.2 起宿主才会在用户打字时重新问插件要状态。少了这一条，0.3.1 的宿主上「测试连接」按钮会一直是灰的——填了地址和令牌也不会变。仍标着 0.3.2 以下的旧构建会在安装时被挡下并提示先升级本程序。

**插件没装或没启用时，主程序里不该有任何东西被当成 K-Vault**：远程类型只从 rclone 自己认的后端和启用的插件里来，`kvault = 1` 这个标记也只有这里在写。

## 第一次用

1. 「连接」页填站点根地址，比如 `https://kv.example.com`，不要自己加 `/dav`。
2. 填令牌（`kvault_` 开头）。留空也行，那样只能用账号密码走 DAV。
3. 点「测试连接」。插件先打 `/api/health`，有令牌再打 `/api/v1/me`，把站点名、权限范围、支持的存储、单文件上限念给你听。
4. 「远程」页确认远程名（默认 `k-vault`）、存放目录、存储后端、是否去重，点「创建远程」。
5. 建完 `k-vault:` 就是一个普通 rclone 远程，主程序里照常用。

测试连接不会写任何东西到站点；建远程只写 rclone 配置，不连站点。

## 站点上的文件

「站点上的文件」这一页有四个动作，请求全由插件拼，主程序只负责发：

| 动作 | 插件做什么 | 主程序做什么 |
| --- | --- | --- |
| 列出文件 | 自己拼 `GET <站点>/api/v1/files?limit=200[&cursor=…]`，带 `Authorization: Bearer …`，一页一轮、最多 5 轮，按 `pagination.listComplete` 停 | 只是把请求发出去 |
| 删除 | 先弹确认框问一句，你点了「是」才拼 `DELETE <站点>/api/v1/file/<id>` | 只是把请求发出去 |
| 上传 | 拼出「发到哪、带什么头、表单里放哪些字段、文件字段叫什么」的请求描述 | 打开你**这次选中的那一个文件**，流式拼成 multipart 发出去 |
| 请求说明 | 把这几个请求原样列出来（令牌只露前四位），不发任何网络请求 | 什么都不做 |

两个细节值得知道：

- 删文件的确认框取消时，插件一个请求都不发。「没答」也按「不删」处理——宁可少删一次。
- 上传时插件只知道文件名，不知道文件大小，所以幂等键（`Idempotency-Key`）由主程序用「插件给的种子 + 文件内容摘要」拼出来。换一次重试不会变成两个文件；这一点插件做不到，只能要求主程序做。

**列目录和上传对「不传路径」的理解不一样，这是故意的。** 主程序的文件页不给路径时就表示「这条远程的根」，所以列目录、删文件拿到的都是真正的根（面包屑上写什么就列什么）；上传不给路径时才落到「连接」页填的上传目录（默认 `image_bed`），这样图床、已有的上传和删除目标都不会因为修了浏览根而换地方。子目录两种情形都一样：给了路径就用给的路径。

「记录名」留空就用「连接」页那一套站点设置；填了就用「旧设置与备份」里扫出来的某条记录，令牌也从那条记录取。

> **上传这一步还等着主程序加一个能力。** 宿主现在只有 `http.request`，它的请求体只能是字符串，拼不出 multipart 的文件段。缺的那个能力叫 `http.upload`，规格写在 [HOST-CONTRACT.md](HOST-CONTRACT.md) 的 H8：只发用户选中的那一个文件、只认宿主自己的授权表、按插件给的字段顺序拼。宿主还没有它的时候，点「上传」会明说「主程序还没有 http.upload 这个能力」，不会假装传了。

## 从旧版迁过来

主程序内建的 K-Vault 和本插件共用同一个 `kv.json`，所以装完插件站点设置和令牌就已经在了。剩下的只是把 rclone 里那些旧远程扫成一份清单，再挑一条照着重建成新远程。详见 [MIGRATION.md](MIGRATION.md)。

「旧设置与备份」页只有四个动作：

| 动作 | 做什么 | 写什么 |
| --- | --- | --- |
| 扫描旧设置 | 列出所有远程，只认带 `kvault = 1` 标记的那些，把地址/目录/存储/去重记进清单 | 只写自己的 kv，**不碰 rclone 配置** |
| 用这条填表单 | 把「记录名」那一条填进「连接」和「远程」两页 | 什么都不写 |
| 导出 | 把站点设置、清单、每远程明文令牌拼成一段 JSON 放进文本框 | 什么都不写 |
| 恢复 | 合并清单、补回令牌，站点设置只在空着时才填 | 只写自己的 kv |

扫描之所以安全，是因为它一个 `config/create`、`config/update`、`config/delete` 都不发：旧远程原样留着，老版本主程序照常能用，两边不打架。代价是它不会替你改旧远程，也不会替你删——名字冲突时删哪个由你决定。

迁移不碰站点，也不碰旧远程，所以「插件禁用后什么都没被当成 K-Vault」这件事在迁移前后都成立：标记只在 rclone 配置里，显示与否看主程序有没有看到启用的插件。

## 令牌存在哪儿

建远程时插件写两处：

- 插件自己那一格 `site`：站点地址、令牌、目录、存储、去重，重开面板要用。
- 远程名那一格，值就是 `{"token": "…"}`：主程序上传前按这个顺序找令牌——先按远程名找这一格，再读 rclone 远程参数里的 `bearer_token`（要走 `config/reveal` 还原），最后才看插件那一格。

第二处是为了让**主程序原来的上传路径继续用**：它在这些插件出现之前就按「远程名 → 明文令牌」存了一份，先查这里。所以用插件建的远程，主程序上传时不需要额外配置；反过来，早先用主程序建好的 K-Vault 远程，装了插件也不会被改写。两处都在同一个文件（`<数据目录>/plugins/kvault/kv.json`）。

**这也是为什么要导出**：宿主的卸载会把这个目录整个删掉，包括那份唯一的明文令牌。

## 面板分页

| 页 | 里面有什么 |
| --- | --- |
| 连接 | 站点地址、令牌、说明、测试连接 |
| 远程 | 远程名、存放目录、存储后端、去重、创建远程 |
| 旧设置与备份 | 扫描旧设置、记录名、填表单、导出/恢复 |
| 站点上的文件 | 记录名、目录、列出文件、文件 id、删除、选文件上传、下载地址、请求说明 |
| 关于 | DAV 地址、复制按钮、上传为什么只交出去字节 |

「当前状态」和「检查项」两块不挂在某一页上，切页时一直可见。切页不会触发插件动作，表单里改了一半的值也不会丢。

## 它不做什么

**它不自己发文件。** 这条要说得直白：插件的请求通道正文只收字符串，几百 MB 的二进制没法先变成一个字符串再发出去。所以插件把请求描述清楚交给主程序，字节由主程序搬。任何「插件能直接上传大文件」的说法都是错的。插件也不申请 `fs`（读你的磁盘）和 `net`（自己开网络连接）：一旦给了，插件就能读任意文件，「只发你这次选中的那一个文件」就没人保证了。

它也不支持只有账号密码、没有令牌的站点：插件写的远程参数里只有 `bearer_token`，没有 `user`/`pass`。这类站点在主程序里照旧能用，只是别指望插件替你配。

还有两件它不肯做的事。建的远程能不能用取决于你连着的 rclone 里有没有 `webdav` 后端，没有就停下来说明，不会硬写一个跑不了的远程；令牌以明文存在本机插件目录（和其它插件一样，没有系统密钥环可用）。

## 权限

`config.json` 里只申请这些：

| 能力 | 用来做什么 |
| --- | --- |
| `kv` | 存站点地址、令牌、远程参数、迁移清单 |
| `ui` | 复制 DAV 地址、复制导出内容到剪贴板、删文件前确认 |
| `http` | 打站点的 `/api/health`、`/api/v1/me`、`GET /api/v1/files`、`DELETE /api/v1/file/<id>`；上传时交出一份请求描述，**插件自己不发字节** |
| `rclone` | 列远程、逐个读参数、解密令牌、查后端列表、创建远程 |
| `remote_types` | 让主程序在类型下拉里显示 K-Vault（元数据，不是能力组） |

`http` 这一格能碰的只有用户自己填的那个站点地址：地址是插件要从面板里读的，插件没有能力连别的地方。

`rclone` 这一格要说清楚：宿主不对 `rclone.call` 做方法白名单，拿到这格就等于拿到整个 rclone RC 接口——包括 `config/delete` 和 `operations/delete`。插件自己只调用 `config/get`、`config/reveal`、`config/providers`、`config/create`、`config/listremotes` 五个，迁移过程中一个写操作都不发；但这道门是宿主那侧才关得上的，插件能做的只有不滥用。

没有 `fs`、`proc`、`net`：插件不读文件、不起进程、不开端口。

## 开发

powershell.exe 不行：Windows PowerShell 5.1 会按 ANSI 读这个带中文的脚本，报 `The string is missing the terminator`。用 PowerShell 7 的 `pwsh`：

```bash
cargo fmt --all --check
cargo test
cargo check --target wasm32-wasip1
pwsh -File scripts/pack.ps1            # Windows
bash scripts/pack.sh                   # Linux / macOS / CI
```

`cargo test` 现在是 77 条，主要分三类（`src/site.rs`、`src/files.rs`、`src/migrate.rs` 的用例按同类归在这三组里）。

一类只测纯函数（`src/api.rs`）：站点地址怎么拼、`id` 怎么转义（`:` 和 `/` 必须留着，站点拿整个字符串当主键）、分页怎么判完、错误信封怎么摊平成一句话、相对下载地址怎么补成整条、令牌怎么遮。

一类拿假宿主把真流程跑一遍（`src/main.rs` 的测试）：列出两页、站点报错时保留站点原话、删除先确认再发、取消时一个请求都不发、上传只要用户选中的那个字段（绝不要路径）、被拒的上传照实报、宿主没有 `http.upload` 时明说是缺这个能力、请求说明不发任何东西也不露令牌。

还有一类真的开 socket（`src/wire.rs`）：起一个本机 HTTP 服务，让插件通过真实的主机代理把请求发过去，断言服务端收到的那一行请求、认证头和翻页参数，断言删除请求的路径，以及上传时文件段的字节与字段顺序。禁用/卸载/迁移三条路也在这类里：没配置站点时一个请求都不发；清单里的旧记录能用旧令牌列出文件。

产物在 `dist/kvault-0.3.2.zip`，打包时顺带算出它的 sha256。

## 在 GitHub 上构建

`.github/workflows/ci.yml` 每次推送、每个 PR，以及每天 19:31 UTC（北京时间 03:31）都会跑一遍：格式、wasm 目标编译、测试、`config.json` 与中英文案自检。依赖或 runner 镜像哪天变了，没人推代码也会在这里露出来。

只要 zip、不想在本机装 Rust 与 wasm 目标：手动跑 **release**（`Actions` → `release` → `Run workflow`，选分支），产物是 artifact `plugin-package`，里面是 `dist/kvault-<版本>.zip`。手动跑不会建 Release —— 那一步只对 `v*` tag 生效；tag、`config.json`、`Cargo.toml`、`Cargo.lock` 四处版本对不上会先被拦住。
